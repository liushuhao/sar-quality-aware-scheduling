2026-09-26 第二篇查新收尾时，我把「三族/知网补检不改变架构设计输入」推成「不用先处理，直接进 A 环节」。用户一句「这三项是不是影响能不能投出去」即翻案：知网中文域是唯一 free-web 够不着的盲区，且恰是竞争最热区（五院总体部/上海卫星工程研究所），若存在直杀 scoop，先跑 A 环节+实验 = 数周沉没。

**Why:** 「检查项不改变下一环节的输入」与「检查项不改变是否该投入」是两个决策问题。查新/证伪类检查的产出是 kill-signal，其价值在沉没成本不对称：检查小时级、实验周级。当时我用了正确判据（cheap falsification first）在上一轮，却在下一轮把它只锚在「架构输入」上，判据漂移。

**How to apply:** 给「要不要先查 X」类推荐时，先问 X 的失败结果会不会推翻已规划投入（而非只问会不会改设计参数）；会推翻 → 前置到投入前，哪怕它不影响任何技术环节。翻转推荐时按 rule 16 三条走（错的事实/失败场景/同判据更优），本例三条全中。
