给某个实体注入**逐实体几何**（本例：每任务自己的斜距 `r0_m`，取代库常数 `lib.geo.R0_m`）后，**凡是拿「库几何下的某个量」当基准去归一化/比较新几何下算出的量的地方，全部会口径分裂**——基准与被测量不在同一口径。

本轮实测五处同根因，每处都表现为**假违规或崩溃**而非错值：
- 预编译/放置器用库几何、评估器用逐实体几何 ⇒ 解落在自己可行集外（8/10），CV 非零崩单元
- 生成器级联的掩码腿用库几何 ⇒ 发出越界的「合法」窗口
- 归一化参考量（`T_env_max` 类）是库几何量、被测量是逐实体量 ⇒ 38 实体假违规（最差 1.1721）
- 诊断读数用库几何 ⇒ 值错；且域外样本若记成 `+inf`，`inf - min = inf >= 阈值` 会读成**相反**结论（无限差 ⇒ 判「触发」）
- 调用链末端未透传新参数

**Why**：新几何参数一路加进来，只有「写它的那几行」会更新；基准量散落在别的模块，没人动。它们的类型没变（都是 float），所以不报错，只是慢慢错。

**How to apply**：
1. 注入前先 grep 出**所有**读该基准量的位置（`lib.geo.R0_m` / 库常数 / 全局配置），列成清单逐条判定「在不在逐实体路径上」；
2. 修法不是把基准也改成逐实体（那会让归一化退化成自比较、失去判别力），而是让基准**在被测量的几何上求同一个上界**——`ref = f(envelope_edge, 该实体的几何)`，预算不变；
3. 注入后跑一次**举一反三扫描**：`grep 基准量` 减去 `grep 覆盖参数`，剩下的逐条判定。本轮该扫描在最后抓出**第六处**（`boundary_rate` 在 C2 路径上仍读库 R0，杠杆项偏 ±42%），因会使已完成的实验失效而记账延后；
4. 对 `None` 表示「用库常数」的分支，**加一条守卫断言逐位不变**（旧族必须零漂移），否则无法证明修复只碰新路径。

**同类变体**：乘性常数（比例、pad 百分比）**不**受此影响——实测窗尾垫是乘性分数，对几何缩放不变；只有**加性/绝对基准量**会分裂。这条区分能省掉一次排查。
